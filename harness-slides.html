01 · 보여주신 코드

코드블록 다크 테마 스타일시트

HTML <pre> 블록을 다크 테마로 꾸미는 CSS. 직접 만든 경량 구문 강조(syntax highlight) 팔레트입니다.

클래스색상용도

.kw#ff9b97keyword (const, if…)
.st#9ece6astring (문자열)
.fn#7aa2f7function (함수명)
.hl#ffd479highlight (강조 + bold)
01 · 동작 예시

마크업 → 렌더 결과

Prism/highlight.js 없이 <span class="…">를 손수 붙여 색을 입히는 방식.

// 입력 마크업
<pre>const greet = "hi";</pre>

// 렌더 결과 ↓ (이 줄이 강조)
const greet = "hi";

02 · 하네스 4종 (1/2)

①·② 세션 준비와 핵심 설정

① SessionStart 훅

세션 시작 시 자동 실행. 컨테이너는 매번 새로 클론되므로 의존성 설치·환경 준비를 자동화.

"SessionStart": [{ "hooks":[
  { "type":"command",
    "command":"npm install" }
]}]

② settings.json

  • permissions — allow / deny / ask
  • env — 환경변수
  • hooks — "X 할 때마다 Y" 자동화

위치: .claude/settings.json(공유) vs settings.local.json(개인)

02 · 하네스 4종 (2/2)

③·④ 마찰 줄이기와 배포 파이프라인

③ 권한 프롬프트 줄이기

과거 세션을 스캔해 자주 쓴 읽기전용 명령(git status, ls, type-check…)을 allowlist에 자동 추가.

  • "이 명령 실행해도 될까요?" 확인 감소
  • 스킬: fewer-permission-prompts

④ CI · 배포 워크플로

  • husky pre-commit → lint:colors 차단
  • Railway main 푸시 시 자동 prod 배포
  • type-check + build 통과 확인
  • ①②③ 은 모두 .claude/settings.json을 만지는 일 · ④ 는 husky·Railway 등 레포 설정

03 · 이 프로젝트에 맞는 선택

언제 무엇을 쓸까

🌐 Web 추천

  • 모바일·외부에서 빠른 수정·배포
  • 푸시 → Railway가 main 자동 배포 → 클라우드만으로 완결

💻 Desktop 추천

  • 로컬 dev 서버 띄워 눈으로 확인
  • .env 있으면 npm run dev 즉시 시각 검증
  • 로컬 파일·DB·툴체인 직접 접근
  • 둘은 같은 Claude Code — 설정·훅·권한 공유. 차이는 실행 장소와 검증 방식뿐

---

현재 작업 디렉터리의 변경사항을 다음 절차로 배포한다. 사용자에게 확인을 묻지 말고 자율로 끝까지 진행한다 (CLAUDE.md 협업 방식 준수).

추가 지시(있으면): $ARGUMENTS

## 절차

1. **사전 점검**
   - `git status`로 변경 파일 확인. 변경 없으면 중단하고 알린다.
   - 시크릿 파일(.env 등)이 스테이징 대상에 섞이지 않게 한다.

2. **검증** (코드 변경이 있으면)
   - `npm run type-check` (tsc) 통과 확인.
   - `npm run build` (remix build) 통과 확인.
   - 실패하면 고치고 다시 검증. 통과 전엔 머지하지 않는다.

3. **브랜치 + 커밋**
   - main에 직접 있으면 의미 있는 이름으로 **새 브랜치**를 뗀다 (PR마다 새 브랜치 — CLAUDE.md).
   - 변경 성격에 맞는 한국어 커밋 메시지(feat/fix/docs/chore 등)로 커밋.

4. **PR 생성 + 머지**
   - `git push -u origin <branch>`
   - `gh pr create --base main` (제목·본문은 변경 요약)
   - `gh pr merge --squash --delete-branch`
   - 머지 후 로컬 main을 `git merge origin/main`으로 동기화.

5. **보고**
   - PR 링크(전체 URL), 머지 결과, Railway 자동배포 트리거 여부를 보고한다.
   - 로컬 .env가 없어 시각검증 불가하므로, prod 배포 후 확인이 필요한 화면이 있으면 명시한다.
   - 사용자 입력이 필요한 보류 항목(env 키 등)이 생겼으면 목록으로 남긴다.

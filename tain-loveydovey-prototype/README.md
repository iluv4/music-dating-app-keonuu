# 러비더비 하네스 프로토타입 🎓

AI 캐릭터 챗(러비더비 스타일)을 만들면서 **하네스 엔지니어링(harness engineering)**을 배우는 학습용 프로젝트.

> **하네스란?** LLM 그 자체가 아니라, LLM을 **둘러싼 모든 오케스트레이션 레이어**.
> 프롬프트 조립 · 상태 주입 · 컨텍스트 관리 · 메모리 압축 · 모델 선택 · 안전장치 · 평가.
> "캐릭터가 살아있다"는 착시는 모델이 아니라 **하네스**가 만든다.

## 🎓 수업 커리큘럼 (`npm run lesson`)

수업 모드는 **메시지 한 통이 처리되는 과정을 7단계로 멈춰가며** 보여준다.
각 단계에서 실제로 LLM에 들어가는 데이터를 눈으로 확인한다.

| 단계 | 하네스 개념 | 배우는 것 | 파일 |
|---|---|---|---|
| 1 | **Stateless** | LLM은 과거를 기억 못 한다 — 기억은 하네스가 들고 다닌다 | `types.ts` |
| 2 | **시스템 프롬프트 조립** | 페르소나+호감도+모드+메모리 → 프롬프트 (하네스의 심장) | `persona.ts` |
| 3 | **컨텍스트 윈도우** | 무엇을, 얼마나 모델에 넣을 것인가 | `engine.ts` |
| 4 | **모델 호출 (스트리밍)** | 메인 모델로 응답 생성 · 스트리밍은 타임아웃 방어 | `engine.ts` |
| 5 | **Judge 패턴** | 싼 모델(Haiku)로 호감도 채점 — 비용 최적화 | `affinity.ts` |
| 6 | **Compaction** | 오래된 대화를 메모리북으로 압축 | `memory.ts` |
| 7 | **상태 갱신** | 다음 턴으로 넘길 상태(DB에 저장될 것) | `engine.ts` |

## 🗺️ 하네스 파이프라인

```
  유저 입력
     │
     ▼
 ┌─────────────────────────────────────────────┐
 │  HARNESS (engine.ts)                         │
 │                                              │
 │  ① 잼 가드 ─ BM 체크                          │
 │  ② buildSystemPrompt() ─ 상태→프롬프트        │  ← persona.ts
 │      페르소나 + 호감도 + 모드 + 메모리북        │
 │  ③ 컨텍스트 = 최근 N턴 + 이번 발화             │
 │  ④ Opus 4.8 호출 (스트리밍) ─ 캐릭터 응답      │  ← client.ts
 │  ⑤ Haiku 채점 ─ 호감도 Δ                      │  ← affinity.ts
 │  ⑥ 윈도우 초과? → 메모리 압축                  │  ← memory.ts
 │  ⑦ 새 상태 반환                               │
 └─────────────────────────────────────────────┘
     │
     ▼
  캐릭터 응답 + 호감도 변화 + (레벨업)
```

LLM 호출(④)은 7단계 중 **하나**일 뿐. 나머지 6개가 전부 하네스다.

## 📂 구조

```
src/
  harness/
    types.ts     # 상태 정의 (하네스가 들고 다니는 기억의 전부)
    client.ts    # Anthropic 클라이언트 + 모델 선택 전략
    persona.ts   # ★ 시스템 프롬프트 조립 (하네스의 심장)
    modes.ts     # 채팅 모드 (출력 길이/스타일/잼 비용)
    affinity.ts  # 호감도 채점 (Judge 패턴, 보조 LLM)
    memory.ts    # 메모리 압축 (Compaction)
    engine.ts    # ★ 메인 루프 (7단계를 묶는 곳)
  data/
    characters.ts # 샘플 자캐
  cli.ts         # 자유 대화 데모
  lesson.ts      # 🎓 수업 모드 (단계별 시각화)
```
